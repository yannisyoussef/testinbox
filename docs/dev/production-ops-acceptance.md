# Production Ops acceptance — TI-006

What the application requires of the OVH production estate before a dark
deployment, stated as acceptance contracts, not instructions
([ADR-034](../adr/0034-production-platform-and-promotion.md),
[production.md](production.md)). Each row: the invariant, how it is proven,
who owns it, and what result blocks TI-006. "Blocks" means TI-006 reports
**APPLICATION SIDE COMPLETE — WAITING ON OPS**, not complete.

Application CI cannot substitute for any row marked Ops. The three
independently re-verified blockers — no monitoring, no backups, no origin
isolation — are rows A, B and C.

| # | area | required invariant | how to prove it | owner | blocks TI-006 if |
|---|---|---|---|---|---|
| **A** | Monitoring | Both deployables' private management ports are scraped; the alert set in [production.md § Observability](production.md#observability--the-alerting-contract) exists, with `testinbox_wait_listen_degraded_polling == 1 for > 1m` and readiness-not-UP as firing rules; the scrape endpoint is reachable from the monitoring runtime and from nowhere wider than the SMTP listener | a scrape of `testinbox_build{service,git_sha}` for `testinbox-api` and `testinbox-ingestion` showing the handed-off commit; each alert rule fired once by a deliberate trigger (e.g. stop ingestion → readiness alert) and recorded | Ops | no scrape, or any listed alert absent or never proven to fire |
| **B** | Backups + restore | A **logical, table-scoped** dump only (no `pg_basebackup`, no WAL archiving — they copy content by construction); only the control-plane tables in `deploy/backup/scope.txt` carry data; no object storage; retention set per the human decision; backups encrypted at rest with access limited to Ops | `scripts/check-backup-scope.sh` run against the real dump, or against `pg_restore -l dump \| awk '/ TABLE DATA / {print $7}'`, exits 0; the backup job's configuration showing the `pg_dump` table scope and no object-storage source, plus a listing of the backup target with no bucket or prefix in it; a **restore drill** into a disposable database: current migrator applies nothing, an API node starts, a managed key that existed at backup time authenticates, `message` and `inbox` are empty | Ops (runtime, drill) · Owner (retention/RPO/RTO decision) | gate fails, drill not performed, a physical/WAL backup, or object storage in any backup |
| **C** | `DOCKER-USER` / origin isolation | TestInbox answers only through the approved ingress path; a direct connection to the origin address is not answered on **any** trust-boundary port: 443, 80, 25, 2525, 9090, 9091, 5432, 9000 | `npm run test:origin` from **outside** the host with `TESTINBOX_ORIGIN_PROBE_ADDRESS` set to the origin's IP literal (every family the origin has an address in), with its built-in same-family positive control passing; evidence that the probed address is the origin's (the interface listing); the `DOCKER-USER` chain non-empty is corroboration, not proof | Ops | any port answers, the proof was run from the host itself, or the address probed is not shown to be the origin's |
| **D** | Production TestInbox stack | Four containers from the handed-off digests exactly; every variable in [production.md § The production environment](production.md#the-production-environment-as-ops-must-set-it) set as listed (`SPRING_PROFILES_ACTIVE=production`, `TESTINBOX_ENVIRONMENT=production`, `TESTINBOX_EDGE_REQUEST_CEILING=100s`, `TESTINBOX_PROXY_READ_TIMEOUT` in 90–100 s, …); stop grace ≥ 90 s API / 60 s ingestion; `restart: unless-stopped`; SMTP bound to a private interface only; web reaches the API by internal name | container image references equal the four handoff digests; `docker inspect` shows the variables and grace periods; both processes log `deployment configuration validated (environment=production profiles=production,deployed …)` at startup; SMTP not reachable from the public interface | Ops | any image by tag, a startup refusal, any grace below the floor, SMTP publicly reachable |
| **E** | Secrets | Every value in [production.md § Secrets](production.md#secrets--names-not-values) provisioned outside Git in the Ops secret store; the synthetic credential is a managed key with `inboxes:write`+`messages:read` only; the administrative credential is distinct and never on a runner; the bootstrap key is ≥ 43 chars of real entropy | each process starts (DeploymentSafety would refuse fixture or short values); `GET /v1/api-keys` with the synthetic key is `403`; the administrative key is held only in the store | Ops | any value in Git, in a workflow, in a label; a synthetic key that can mint keys |
| **F** | DB / session | PostgreSQL 16 reached **directly** — no PgBouncer, no transaction-mode pooler; `idle_in_transaction_session_timeout = 30s` effective for the application role and **persisted** (`ALTER SYSTEM`/`ALTER ROLE`, not a session `SET`); `max_connections` clears both pools + LISTEN + migrator | API readiness shows `waitNotifier.listening=true` and `dbSession.bounded=true, enforced=true`, and still does after a PostgreSQL restart; the synthetic parked-wait test resolves in < 750 ms after the SMTP `250`; `testinbox_wait_listen_degraded_polling == 0` | Ops | `dbSession` OUT_OF_SERVICE (node will not become ready in production), the setting lost on restart, degraded polling `1`, or a pooled endpoint |
| **G** | Storage isolation / quotas | The bucket exists before first start; runtime credentials scoped to it with no `CreateBucket`; the store is private to the compose network; a storage quota or volume ceiling exists above the ADR-027 bound (`maxStoredBytes` + ingest-rate overshoot) | readiness `objectStorage: UP` with `TESTINBOX_S3_CREATE_BUCKET=false`; an attempt to create a bucket with the runtime credentials is refused; the console/API is unreachable publicly | Ops | creation succeeds with runtime credentials, or the bucket had to be created by the application |
| **H** | Handoff consumption | The production pipeline runs on a **protected production ref**; it derives the environment **from the ref it runs on, never from the `TESTINBOX_ENVIRONMENT` variable** (a GitLab trigger token is project-scoped, so the staging token could otherwise request a production reconcile); the staging token's creator cannot run pipelines on that ref; it **verifies the digest set equals the one its staging reconcile recorded as proven** before deploying; it refuses tags, malformed digests, images outside `ghcr.io/yannisyoussef/testinbox-*`, and incomplete sets; at most one production reconcile at a time, never cancelled mid-migration | the ref's protection settings; a trigger with the **staging** token against the production ref is refused; a dry handoff of the current staging digest set is accepted and correlated; a handoff of a digest set staging never proved is **refused**, recorded | Ops | the environment is taken from the variable, the staging token can reach the production ref, the pipeline deploys without the staging correlation, or accepts a non-digest reference |
| **I** | Migration execution | Exactly one `migrator` run per reconcile, to completion, before any service is updated; a non-zero exit aborts with services untouched; bounded by a timeout; a reconcile in progress is **never cancelled mid-migration** — a later candidate queues behind it | reconcile log showing migrator exit 0 then service update; an induced migrator failure (wrong DB password) leaving the running services untouched; two candidates handed off in quick succession applied in order, neither interrupted | Ops | services updated before or despite a failed migration, or a reconcile interrupted |
| **J** | Readiness | Reconcile waits on `/actuator/health/readiness` of API and ingestion (not liveness, not "container running"); readiness includes `db, schema, objectStorage, waitNotifier, dbSession` (API) and `db, schema, objectStorage, smtpListener` (ingestion) | readiness bodies captured post-reconcile with every component `UP` | Ops | reconcile declared done on a non-ready node |
| **K** | Post-deployment synthetics | `npm test` (gate) and `npm run test:identity` pass on the host after every reconcile; `npm run test:product` passes with the administrative credential; JUnit reports retained | reports with ≥ 13 gate tests, 0 skipped, 0 failed; identity suite showing both deployables on the handed-off commit | Ops | any skip, any failure, or a suite not run |
| **L** | Rollback | A previous approved candidate can be re-handed and deployed by the same path with no rebuild; readiness and synthetics follow; the previous digest set is durably recorded | one rehearsed rollback on production before go-live: hand off candidate N-1, reconcile, readiness, `npm test`; then N again | Ops | rollback requires a rebuild, or is untested |
| **N** | GitHub `production-handoff` environment | Deployment branches restricted to `master`; a required reviewer; the production trigger token and `GITLAB_OPS_API_URL` / `GITLAB_OPS_PRODUCTION_REF` set on that environment and nowhere else | `gh api repos/yannisyoussef/testinbox/environments/production-handoff` showing the `master` branch policy and the reviewer (both exist as of 2026-09-19); the secret and variables listed on the environment | Owner | the branch policy or reviewer removed, or the token present at repository scope |
| **M** | Dark-deployment verification | All of A–L, and: no MX record, no public TCP/25, no edge→ingestion relay configured, no tenant traffic, `testinbox_smtp_accept_total` moves only for the synthetic sender | DNS query showing no MX for `inbox.testinbox.email`; external port scan of the edge and origin; the edge's transport still `discard:`; counters | Ops · Owner declares "dark" only with this evidence | any of those is live, or evidence is asserted rather than shown |

  **legal/compliance activation** — human gates recorded in ADR-004; this
